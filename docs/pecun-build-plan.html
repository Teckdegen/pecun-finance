PECUN Finance · Plan v1 · 13 Nov 2026

One app for every on-chain APY, executable on any chain

PECUN lists every yield opportunity on-chain, and lets users deposit and withdraw from one Turnkey wallet. PECUN pays the gas and takes a fee on each deposit and withdrawal.

Architecture

Four layers. The UI only talks to one common interface, so adding a protocol means adding one adapter file.

Layer 1: Catalog (only what we can execute)

The catalog is built from our own adapters. Every adapter's getOpportunities() returns the vaults it can deposit into and withdraw from, with APY and TVL from that protocol's own API or on-chain reads. Merkl adds reward APRs on top. If we can't execute it, it isn't listed. A server job refreshes the data every few minutes and caches it; browsers never call these APIs directly.

Layer 2: Generic executors

One piece of code per standard covers hundreds of protocols:

  • ERC-4626 vaults (Yearn v3, Morpho vaults, Euler, Ember EVM, Upshift, Lagoon, sUSDS, sUSDe and more)
  • Aave-style lending (Aave and its forks)
  • Compound-style lending (Compound v2/v3 and forks)
  • Uniswap v2/v3 and Curve-style LP
  • Simple liquid staking (stake() / mint calls)

Layer 3: Protocol adapters

Dedicated adapters for protocols that don't follow a standard, all using the same interface:

interface YieldAdapter {
  getOpportunities(): Promise<Opportunity[]>
  planDeposit(user, opportunity, amount): Promise<Plan>
  planWithdraw(user, position, amount): Promise<Plan>
  getPositions(user): Promise<Position[]>
}

// Same shape as Sentora's Plan type:
interface Plan {
  steps: UnsignedTx[]   // in order; the fee transfer is added to these
  blockers: Blocker[]   // reasons the action would fail (balance, cap, paused…)
}

Every adapter returns a Plan: the transactions to sign, in order, plus a list of blockers, the reasons the action would fail (not enough balance, vault cap reached, vault paused). The UI shows blockers before the wallet opens, so users never sign a transaction that will fail. One shared send function then handles every protocol and every chain. This copies Sentora's design.

Layer 4: Routing (best and cheapest route wins)

Turns "any token, any chain" into the token the vault needs. For every deposit, PECUN asks several providers for a quote at the same time and picks the one that delivers the most to the vault after all fees and gas, with speed as the tie-breaker.

Deposit, withdraw and gas

The fee transfer and the vault action happen in one atomic transaction. If the deposit fails, the fee is not taken.

Deposit

User picks vault + amount→ Route (swap/bridge if needed)→ Fee → treasury→ Deposit the rest→ PECUN co-signs as gas payer

Withdraw

User picks position→ Redeem from vault→ Fee → treasury→ Rest → user

Delayed withdrawals (Ember, Upshift, unstaking on many chains) pay out later, straight to the user. For these, the fee is taken in vault shares when the withdrawal is requested. The portfolio page shows pending withdrawals and when they're expected.

How it's made atomic, by chain

ChainFee + action in one transactionGas paid by PECUN
SuiOne programmable transaction block (PTB): split the fee coin, transfer it, deposit the rest.Sponsored transaction: the server wallet is the gas owner and co-signs.
SolanaOne transaction with several instructions: fee transfer + deposit.The server wallet is the fee payer and co-signs.
EVMEIP-7702 batching from the user's Turnkey wallet, or a small PECUN fee router contract as a fallback.Turnkey gas sponsorship (already used in the reference demo).
Cross-chainLI.FI integrator fee is taken during the bridge or swap; the vault fee is still taken on the destination chain.Paid on both chains.

Gas economics. Because PECUN pays gas, small deposits on Ethereum mainnet lose money. Example: a $20 deposit at a 0.2% fee earns $0.04, but gas can cost over $1. Use a minimum fee per chain (for example, 0.2% or $0.50, whichever is higher) or a minimum deposit on expensive chains.

Treasury float. The server wallet must hold ETH on each EVM chain, plus SOL and SUI. Add low-balance alerts and an automatic top-up from fee income.

How each one gets listed in the UI: if a protocol has an execution SDK, the same SDK (or the protocol's own app API) returns its list of vaults, markets or pools. That list is the adapter's getOpportunities(). Lagoon, Suilend and Gearbox have no public list endpoint, so their adapters read the list through the SDK or on-chain.

Not usable under the "free" rule: Yield.xyz and Enso (both need an API key). Odos could not be confirmed. ether.fi, Haedal, Rocket Pool and Veda have no SDK on npm, so they need direct contract calls.

Checked on 14 Nov 2026 and left out on purpose:

  • Drift: drained for about $285M in April 2026. Its main spot markets (USDC, SOL, JLP) still sit at 100% utilization with borrow rates at their maximum, so deposits can't be withdrawn. Not listed.
  • Fluid on Solana and Sui: on Solana, Fluid's lending runs as Jupiter Lend, which is already listed (the program IDs in @instadapp/fluid-solana-sdk don't exist on mainnet). The Sui deployment holds only a few dollars. Neither SDK is installed.
  • Aave "Simple Earn" vaults: neither Aave API offers a list of them; vaults can only be looked up by address or owner.
  • compound-js: not installed. It pins ethers v5 as a peer dependency, which conflicts with @aave/client's ethers v6 and breaks npm install. Comet calls are made with viem instead.
  • Moonwell and Spark Morpho vaults: already listed through the Morpho adapter, so they are not repeated.
  • SparkLend on Gnosis: read, but every reserve is frozen, so nothing is shown.

Build phases

  1. Foundation. Fork the Turnkey demo pattern into the PECUN app: login, EVM + Solana wallets, then add Sui wallets. Set up the treasury server wallet and gas sponsorship on all three chains.
  2. Catalog. The explore page fed by adapters plus Merkl, with filters (chain, asset, type, TVL, APY) and risk labels.
  3. Legal. The unsupported-regions disclaimer, PECUN terms, and the per-protocol legal record (below), before any deposit button goes live.
  4. Fee and gas engine. Atomic fee + action builders for Sui PTBs, Solana multi-instruction transactions and EVM 7702 batches, with tests on testnets.
  5. First adapters. The generic ERC-4626 adapter, then Ember, Upshift, Morpho, Aave, NAVI, Suilend and Kamino.
  6. Portfolio. Positions across chains, pending withdrawals, fee and earnings history.
  7. Routing. A quote engine that asks Relay, LI.FI, Across, deBridge and Mayan (cross-chain) plus Kyber, Velora, Jupiter and Cetus/7k (same-chain) in parallel and picks the best net route.
  8. Breadth. Pendle, Lido, Scallop, Aftermath, Jupiter Lend, Hyperliquid, LP adapters, native staking per chain, then more chains.

Legal plan

PECUN is a licensed operator. This section tracks what PECUN's own terms must cover and what each integrated partner's terms require.

Platform-level issues (apply to PECUN itself)

TopicWhy it mattersWhat we do
CustodyHolding user funds can trigger money-transmitter or custody licensing.Stay non-custodial: users control their Turnkey wallets. The server wallet only ever holds PECUN's own fees and gas money. No contract of ours holds user balances between steps.
Fees on transactionsCovered by PECUN's license.Show the exact fee before every signature and keep a fee history per user.
Investment adviceRanking or recommending yields can read as advice.Present data, not recommendations. Label APY as variable and historical.
Unsupported regionsIntegrated protocols exclude certain regions.Publish the unsupported-regions list and disclaimer (below).
PrivacyEmail and social login collect personal data.Privacy policy, data-protection compliance for each market (for example GDPR in the EU), and Turnkey's data processing terms.
TaxSome countries require reporting from platforms that facilitate crypto transactions.Keep full fee and transaction records. Offer users a CSV export of their history.
Third-party termsLI.FI, Turnkey and each protocol have their own terms.Reference them in PECUN's terms where required (LI.FI requires this). Licenses are summarized below.

Terms review results

Read from each protocol's own terms on 13 Nov 2026. "Sanctioned" means the usual list: Cuba, Iran, North Korea, Syria, and Russian-occupied regions of Ukraine, plus anything on OFAC, EU, UN or UK lists. A blank or "not stated" means the terms didn't say, not that it's allowed.

Key points

US is excluded. Ember, Upshift, Hyperliquid, Jupiter, Kamino, LI.FI and Lido Earn all exclude the US, so it's on the unsupported list.

Ember and Upshift terms say "internal use only" for their own website. Ember is already a partner; confirm the integration with both in writing as a formality.

Turnkey requires PECUN to screen users under its own compliance policy, which PECUN's licensed setup covers.

VPN clauses. Nearly every protocol bans using a VPN to get around its region rules; PECUN's terms should say the same.

Pre-launch checklist

  • PECUN terms of service, risk disclosures and privacy policy published
  • Unsupported-regions list and disclaimer live at sign-up
  • Registry record completed and reviewed for every protocol with an Execute badge
  • Fee shown before every signature, with a fee history in the portfolio
  • Integrator terms accepted where protocols require them (and LI.FI integrator fee set up)
  • Treasury low-balance alerts and top-up process on every chain
  • Testnet runs of deposit and withdraw for every adapter
  • Contract audit if a PECUN fee router contract is deployed

Open questions

  • Fee rate: flat percentage, tiered by size, or different per chain?
  • Minimum fee or minimum deposit on Ethereum mainnet?
  • Suilend publishes no terms: ask them before integrating, or skip it?
  • Will PECUN run its own KYC to unlock KYC-gated vaults (RWA), or leave them out?
  • Which chains come after EVM, Solana and Sui?
